# 3D 오목 (입체 오목) 미니게임

`1VS1 Game` 미니게임 모음 중 하나. 기존 평면 오목에 높이(z축) 개념을 더해 15x15x15 입체 격자에서 진행하는 1대1 대결 게임.

## 게임 설명

- 기존 오목처럼 5개를 한 줄로 이으면 승리
- 다만 평면이 아니라 **15x15x15 입체 격자**(3375칸)에서 진행됨
- 플레이어는 바둑판의 (x, y) 교차점만 선택 — 커넥트4처럼 중력에 따라 그 기둥의 가장 낮은 빈 칸에 돌이 자동으로 쌓임(z는 선택 불가, 자동 결정)
- 가로 / 세로 / 높이 / 평면 대각선 / 입체 대각선을 합친 **13방향** 중 어느 쪽으로든 5개가 이어지면 즉시 승리
- 보드가 가득 찼는데 승자가 없으면 무승부(15x15x15 규모상 사실상 거의 발생하지 않음)
- Photon PUN2 기반 실시간 1대1 대전. 접속이 안 되어 있으면 한 화면에서 번갈아 두는 로컬 핫싯 모드로 자동 전환

## 조작법

| 입력 | 동작 |
| --- | --- |
| 좌클릭 | 마우스가 가리키는 교차점에 내 턴일 때 돌 놓기 |
| 우클릭 드래그 | 시점 조절 — 아래로 내리면 바둑판, 위로 올리면 맞은편 상대방 얼굴이 보임(좌우는 제한된 범위만 회전) |
| 마우스 휠 | (사용 안 함) |
| **Q** | 내 턴일 때 보드를 왼쪽(반시계)으로 90도 회전 |
| **E** | 내 턴일 때 보드를 오른쪽(시계)으로 90도 회전 |

- 카메라는 마주 앉은 좌석에 고정된 1인칭 시점(자유 이동 불가). 보드 회전은 턴을 소모하지 않는 자유 행동이며, 내 턴이 아닐 때는 동작하지 않음.

## 구현 방식

씬: `Assets/Scenes/MiniGame_Gomoku3D.unity` · 스크립트: `Assets/Scripts/GOMOKU MINIGAME/`

| 스크립트 | 역할 |
| --- | --- |
| `GomokuGrid.cs` | 순수 C# 클래스(MonoBehaviour 아님). `int[,,]` 보드 데이터 관리, 배치 가능 여부/실제 배치 좌표 계산 |
| `GomokuWinChecker.cs` | static 유틸. 13방향 벡터를 검사해 승리 여부와 승리 라인 좌표를 반환 |
| `GomokuTurnManager.cs` | `MonoBehaviourPun` 싱글턴. 턴/게임 상태 관리, 돌 배치·상대 아바타 머리 회전·보드 90도 회전을 전부 같은 PhotonView RPC로 동기화(돌 배치는 결정론적 로직이라 좌표+플레이어 번호만 전송하면 양쪽이 동일한 결과에 도달) |
| `GomokuStoneSpawner.cs` | 그리드↔월드 좌표 변환, 나무색 베이스 플레인+격자선+돌을 런타임에 자동 생성. 보드 전체가 중심 피벗의 회전 가능한 부모(`boardRoot`) 아래 묶여 있어 이미 놓인 돌까지 통째로 부드럽게 회전 |
| `GomokuInputHandler.cs` | 바둑판 지면과의 평면 교차 계산으로 (x,y) 클릭 판정(카메라 각도·보드 회전 각도와 무관하게 정확), 선택 가능 교차점 마커 표시, Q/E 입력 처리 |
| `GomokuVisualHighlighter.cs` | 승리 시 승리 라인에 해당하는 돌 색상 변경 + 펄스 애니메이션 |
| `GomokuSeatedCamera.cs` | 1인칭 착석 시점 카메라. 보드 크기에 비례한 눈높이/좌석 거리 계산, 양쪽 좌석에 아바타(캡슐+구체) 생성 후 내 아바타는 숨기고 머리 회전만 RPC로 상대에게 실시간 전파 |

돌/보드 재질, 아바타 프리팹은 전부 비워두면 기본 도형(Sphere/Plane/Capsule)으로 자동 생성되며, 커스텀 프리팹·머티리얼을 인스펙터에 연결하면 그대로 대체됨.
